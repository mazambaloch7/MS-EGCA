============================================================
SECTION 7: PROPOSED MODEL ARCHITECTURE
============================================================

Implement MilGraph-CalibNet in pure PyTorch.

Do NOT use torch_geometric.

Architecture:

Input RGB image
→ CNN/Foundation backbone
→ patch/token feature extraction
→ kNN graph construction from patch embeddings
→ Graph Attention Network / MPGR module
→ multi-scale feature fusion
→ discriminative patch attention pooling
→ prototype contrastive classifier
→ calibrated prediction

Main architecture classes:

1. PatchFeatureExtractor
2. KNNGraphBuilder
3. GraphAttentionLayer
4. MPGR
5. MultiScaleFusion
6. DiscriminativePatchAttention
7. PrototypeContrastiveHead
8. MilGraphCalibNet

Detailed design:

PatchFeatureExtractor:
- use ConvNeXt/ConvNeXtV2/DINOv2-like backbone where available
- extract patch-level tokens
- if backbone output is B,C,H,W, convert to B,N,C
- if backbone output is B,N,C, use directly
- reduce token dimension to CONFIG["EMBED_DIM"]
- limit tokens to CONFIG["MAX_PATCH_TOKENS"]

KNNGraphBuilder:
- input patch tokens B,N,C
- normalize tokens
- compute cosine similarity matrix B,N,N
- select top-k neighbors
- k = CONFIG["KNN_K"]
- avoid sparse tensors
- return neighbor indices and similarity weights
- if DirectML fails, build kNN on CPU and return indices to device

GraphAttentionLayer:
- multi-head graph attention over kNN neighbors
- no torch_geometric
- use gather/indexing carefully
- compute attention scores for center node and neighbor nodes
- apply softmax over neighbor dimension
- aggregate neighbor features
- residual connection
- dropout
- layer normalization
- return updated node features and attention weights

MPGR:
Military Patch Graph Reasoning module:
- stack 1 or 2 GraphAttentionLayer blocks
- output relation-aware patch tokens
- save graph attention weights for visualization

DiscriminativePatchAttention:
- learn patch importance scores
- compute attention-weighted feature
- return pooled feature and attention map
- attention map must be visualizable as patch heatmap

MultiScaleFusion:
- fuse:
  global average pooled features
  graph pooled features
  attention pooled features
  optional backbone-level pooled feature
- use MLP + LayerNorm + dropout
- output fused representation

PrototypeContrastiveHead:
- learn one prototype per class
- normalize features and prototypes
- compute cosine-similarity logits with learnable temperature
- return logits and embeddings

MilGraphCalibNet:
- flags:
  use_gnn=True/False
  use_calibration_loss=True/False
  use_contrastive_loss=True/False
  use_multiscale=True/False
  use_patch_attention=True/False
  use_prototype_head=True/False

Forward output must be a dictionary:

{
    "logits": logits,
    "features": features,
    "patch_tokens": patch_tokens,
    "patch_attention": patch_attention,
    "graph_attention": graph_attention
}

SECTION 8: LOSS FUNCTIONS
============================================================

Implement these losses:

1. SoftTargetCrossEntropy
2. CrossEntropyLoss with label smoothing
3. FocalLoss
4. SupervisedContrastiveLoss
5. PrototypeContrastiveLoss
6. BrierLoss
7. CalibrationRegularizationLoss
8. CFRL

CFRL:
Calibration-aware Focal Regularization Loss

Formula:

Total Loss =
CrossEntropy
+ lambda_focal * FocalLoss
+ lambda_contrastive * ContrastiveLoss
+ lambda_calibration * BrierLoss

Default:
lambda_focal = 0.5
lambda_contrastive = 0.1
lambda_calibration = 0.05

Loss must:
- support hard labels
- support soft labels from MixUp/CutMix
- work with model output dictionary
- handle missing features gracefully
- disable components for ablations

Ablation mapping:
- without GNN: use_gnn=False
- without calibration loss: lambda_calibration=0
- without contrastive loss: lambda_contrastive=0
- without multi-scale fusion: use_multiscale=False
- without patch attention: use_patch_attention=False
- backbone only: disable GNN, patch attention, multiscale, prototype head
